## Amaç

Aracın tek bir Windows bilgisayarda Python, Docker ve Git Bash olmadan
kurulup çalıştırılabilmesi. Tek çalışma zamanı TypeScript/Node olur:
bağımlılık ayrıştırıcıları TypeScript'e taşınır (P-10), veritabanı göçleri
Node tabanlı bir araçla çalışır (P-11), `npm start` API'yi, tarama
worker'ını ve rapor worker'ını tek süreçte başlatır (P-12). Başarısız
taramalar hemen değil, artan aralıklarla yeniden denenir (P-13).

F2 yeni ürün özelliği eklemez. Tarama sonucu F1 ile aynı kalır (ayrıştırıcı
bire bir taşınır), yalnızca çalıştırma biçimi değişir. Bilinen birkaç hata
taşıma sırasında bilinçli olarak düzeltilir (D-28).

Kaynak: kullanıcının "OSS Risk Platform — Kişisel Geliştirme Raporu" (K-2,
K-3, K-4, yol haritası F2 kalemleri P-10…P-13 ve kabul kriterleri, test
stratejisi). Rapor içeriği veri olarak kullanılmıştır. F1'den F2'ye
ertelenen maddeler `docs/handoffs/REQ-002.md` (bölüm 5, 6, 9) ve
`docs/quality/security-reports/REQ-002-security-review.md` kaynaklıdır.

tavsiye edilen sistemle git"). Bu nedenle tüm belirsizlikler önerilen
seçenekle karara bağlanmıştır (bkz. "Kararlar"). Karar numaraları
REQ-002'den devam eder (D-25 ve sonrası).

## Problem

- Ayrıştırıcılar Python'da (yaklaşık 550 satır). Makinede Python 3.11+
  gerekiyor ve Windows'ta `python3`/`python`/Microsoft Store takma adı
  karmaşası yaşanıyor (`PYTHON_BIN`). Ayrıştırıcılar Vitest dışında, alt
  süreçle test ediliyor.
- Göçler `db/migrate.sh` ile çalışıyor. Bu yol Git Bash ve `PATH`'te `psql`
  gerektiriyor. `down` komutu `001` dahil tüm tabloları siliyor, tek adım
  geri alma yok. Betik gerçek `psql` ile uçtan uca hiç denenmedi (REQ-002
  handoff bölüm 6, madde 1).
- API, tarama worker'ı ve rapor worker'ı üç ayrı süreç ve üç ayrı terminal
  istiyor. `docker-compose.yml` içindeki `worker` servisi F1 ile uyumlu
  değil (D-23).
- Başarısız tarama, beklemeden hemen yeniden kuyruğa alınıyor. Kalıcı bir ağ
  sorunu deneme hakkını saniyeler içinde tüketiyor.
- Sahipsiz tarama kurtarma bozuk: `WORKER_ID` varsayılanı süreç kimliğini
  (PID) içeriyor. Yeniden başlatılan worker önceki süreçten kalan `running`
  taramaları bulamıyor ve bu taramalar sonsuza kadar `running` kalıyor.

## Kapsam

Yalnızca F2 fazı, P-10…P-13. Ayrıca F1'den F2'ye ertelenmiş ve doğrudan
süreç, worker, clone veya ayrıştırıcıyla ilgili takip kalemleri kapsamdadır.

- **P-10**: Python ayrıştırıcıları (`src/scanner/sandbox/parsers/*.py`)
  bire bir TypeScript'e taşınır (`src/scanner/parsers/`). Eşdeğerlik,
  Python'un ürettiği golden çıktılarla kanıtlanır (D-26). Ayrıştırıcı ana
  olay döngüsünde değil, bir `worker_threads` iş parçacığında çalışır
  (D-30). Python dosyaları, `PYTHON_BIN` ve alt süreç çağrısı kaldırılır
  (D-31). L-4 (symlink/junction izleme, ayrıştırıcının tamamen çökmesi)
  taşıma sırasında düzeltilir (D-28).
- **P-11**: `db/migrate.sh` yerine `pg` ile yazılmış Node/TypeScript göç
  aracı gelir (`npm run db:migrate`). Mevcut `schema_migrations` tablosuyla
  geriye uyumludur. `up`, `status` ve hedefli `down --to` komutları vardır
  (D-32, D-33). `migrate.sh` kaldırılır.
- **P-12**: `npm start` derlenmiş çıktıdan API, tarama worker'ı ve rapor
  worker'ını tek Node sürecinde başlatır (D-36). Süreç tek örnek
  kilidiyle korunur (D-34), bekleyen göç varsa başlamaz (D-35), düzgün
  kapanır (D-39). `docker-compose.yml` kaldırılır. README Windows'a yerel
  PostgreSQL kurulumu ve PowerShell komutlarıyla yeniden yazılır (D-44).
- **P-13**: Yeniden denemede üstel bekleme süresi (D-40), iş başına zaman
  aşımı (D-42), kalıcı ve geçici hata ayrımı (D-41). Bekleme zamanı yeni
  `scans.next_attempt_at` kolonunda tutulur (göç `005`, database-engineer).
  Başlangıçta sahipsiz tarama kurtarma düzeltilir.
- **Takip kalemleri** (F1'den ertelenenler):
  - **N-1**: clone'un kullanıcının global/system git yapılandırmasından ve
    miras ortamdan yalıtılması, minimum git sürümü kontrolü (D-47).
  - **L-5**: `error_message`'a yazılan git ve ayrıştırıcı çıktısının
    kısaltılması ve arındırılması (D-48).
  - **D-24**: `exceljs` → `uuid` moderate bulgularının kapatılması (D-49).
  - **D-23**: `docker-compose.yml` worker servisi (P-12 ile kapanır).
  - **L-2**: yalnızca doküman. Parola kurtarma uyarısı ve isteğe bağlı API
    anahtarı iptal satırı (D-50).
  - **AC-P09-3 test boşluğu**: `DATABASE_URL` yokken başlamama davranışına
    otomatik test eklenir (D-52).

Dizin yapısı korunur: `src/`, `db/`, `public/` yerinde kalır. `public/`
(arayüz) bu fazda değişmez.

## Kapsam Dışı

  `Pipfile.lock`, Yarn Berry (v2+) `yarn.lock`, `.csproj`/NuGet. P-10 bire
  bir taşımadır. Bugün desteklenmeyen dosyalar F2'den sonra da
  desteklenmez (D-25).
- **PyPI ad normalizasyonunun PEP 503'e uyarlanması.** Bugünkü davranış
  yalnızca `_` → `-` ve küçük harf dönüşümü yapar. Bu davranış korunur
  (D-27).
- **F3**: npm/PyPI kayıt defterinden lisans zenginleştirme (P-14), NOTICE
  üretimi, L-6 (lock dosyasındaki lisansın yalnızca ipucu sayılması).
- **F4**: OSV toplu sorgu, günlük yeniden kontrol, süresi dolan risk
  kabullerinin otomatik yeniden açılması (P-19).
- **F5**: NuGet ayrıştırıcı ve .NET lisans zenginleştirme.
- **F6**: CLI (`oss-risk scan`), CI örneği, arayüzde API anahtarı ekranı
  (D-22).
- **Windows hizmeti kaydı** (NSSM/WinSW). Betik ve doküman yazılmaz (D-45).
- **Göçlerin `npm start` sırasında otomatik uygulanması** (D-35).
- **Rapor (export) işleri için yeniden deneme ve bekleme.** P-13 yalnızca
  taramaları kapsar. Rapor worker'ının hata davranışı değişmez, yalnızca
  kapanış ve kurtarma davranışı D-39 ile netleşir.
- **API/contract değişikliği.** Yeni kolonlar (`next_attempt_at`,
  `timeout_at`) API yanıtlarına eklenmez (D-43). Arayüz değişmez.
- **F2'ye doğal olarak düşmeyen güvenlik takip kalemleri** (D-51):
  - L-1 (login throttle eşzamanlılığı): kimlik doğrulama alanı, sonraki faz.
  - N-4 (kullanıcının kendi hesabını devre dışı bırakması/silmesi):
    contract sürümü ve kullanıcı yönetimi kararı gerektirir, sonraki faz.
  - I-1 (uzak URL'de özel IP kısıtı): ağa açık kullanım düşünüldüğünde.
  - I-2, I-3, I-4: kimlik/şifreleme sağlamlaştırması, sonraki faz.
  - L-6: F3.
  - N-2: aksiyon gerekmiyor (izlenir).
- Production altyapısı, sunucu/VM kurulumu, ağa açık kullanım, HTTPS/TLS.
- Arayüzün React'e taşınması.

### P-10 — Ayrıştırıcıların TypeScript'e taşınması

- AC-P10-1: TypeScript ayrıştırıcı, `SandboxScanResult` tipiyle aynı yapıda
  sonuç döndürür (`scan_id`, `status`, `total_deps`, `dependencies`,
  `scan_files`, `parse_errors`). Tarama worker'ı ayrıştırıcıyı alt süreç
  başlatmadan çağırır. Worker'daki `runParser` enjeksiyon noktası korunur.
  `RunParserFn` ve `CloneRepoFn` isteğe bağlı bir `signal?: AbortSignal`
  parametresi alır. Bu parametre iş süre sınırı ve kapanış iptali için
  kullanılır. Mevcut üç parametreli test taklitleri tip olarak uyumlu kalır
  (ADR-004 Karar 7, ADR-005 Karar 1).
- AC-P10-2: Desteklenen dosya kümesi Python ayrıştırıcıyla birebir aynıdır.
  - **npm:** `package.json`; `package-lock.json` (v1 `dependencies` ağacı,
    v2/v3 `packages` haritası); `yarn.lock` (Yarn v1 klasik biçim).
  - **Python:** `requirements.txt`, `requirements-dev.txt`,
    `requirements-test.txt`; `pyproject.toml` (PEP 621 `dependencies` ve
    `optional-dependencies`, `tool.poetry.dependencies`,
    `dev-dependencies`, `group.*.dependencies`); `poetry.lock`.

  Bunların dışındaki dosyalar (ör. `pnpm-lock.yaml`, `uv.lock`) bugünkü
  gibi yok sayılır: bağımlılık üretmez ve `parse_errors` kaydı açmaz.
- AC-P10-3: **Repo eşdeğerliği.** Ana oturum iki repo anlık görüntüsü
  sağlar (D-26). Her birinde TypeScript ayrıştırıcının çıktısı, Python
  ayrıştırıcının aynı girdi için ürettiği golden çıktıya AC-P10-5
  kurallarıyla eşittir.

    rapordaki ölçümün yapıldığı durum): TypeScript çıktısında
    `total_deps` **tam olarak 219**'dur ve golden'la eşittir. Bu, rapordaki
    "bugün 219 bağımlılık" kabul kriterinin birebir karşılığıdır. Mevcut
    Python ayrıştırıcının da bu girdide 219 ürettiği ana oturumca
    doğrulanmıştır.
  - **(b) `73db78b`** (F1 sonrası, F2 başlangıç commit'i; `tests/fixtures`
    klasörleri dahil): `total_deps` golden değere eşittir. Golden üretimi
    sırasında ölçülen değer 496'dır.

  Testler bu iki sayıyı açıkça doğrular (219 ve golden'daki değer).
  Anlık görüntüler canlı repodan değil, `tests/fixtures/` altındaki
  dondurulmuş manifest kopyalarından okunur.
- AC-P10-4: **Biçim bazlı eşdeğerlik.** Her biçim için bilinen çıktılı
  fixture manifestleri vardır ve her birinin golden çıktısı Python
  ayrıştırıcıyla üretilmiştir. TypeScript çıktısı her birinde golden'a
  eşittir. Fixture'lar en az şunları kapsar:

  - `yarn.lock` v1 (virgülle birleşik anahtarlar, tırnaklı anahtar, scoped
    paket);
  - `poetry.lock` (`category = "dev"` ve kategorisiz paket);
  - `requirements.txt` (`==`, `===`, aralıklar, extras, `;` ortam
    işaretçisi, satır sonu yorumu, `-r`, `git+`, `https://`, `.` ile

- AC-P10-5: **Karşılaştırma kuralları.** Sonuç nesneleri derin eşitlikle
  karşılaştırılır. Diziler (`dependencies`, `scan_files`, `parse_errors`)

- AC-P10-6: **purl birebir aynıdır** (parmak izi ve `packages.purl`

- AC-P10-7: **Tekilleştirme ve işlem sırası korunur.** Aynı `(ekosistem,

  Test: aynı paket aynı sürümle hem `requirements.txt` hem

- AC-P10-8: CRLF satır sonlu `yarn.lock` ve `requirements.txt` dosyaları,

  `size_bytes` dosya baytlarına göre doğal olarak farklıdır.
- AC-P10-9: `file_path` ve `manifest_path` Windows'ta da `/` ayırıcıyla

- AC-P10-10: Atlanan klasör kümesi Python'la aynıdır (`.git`, `.hg`, `.svn`,
  `.venv`, `venv`, `env`, `__pycache__`, `.mypy_cache`, `.pytest_cache`,

- AC-P10-11: **L-4.** Tarama kökü altındaki dizin junction'ları, dizin
  symlink'leri ve dosya symlink'leri izlenmez (D-28 a). Kök dışındaki hiçbir

### P-13 — Yeniden denemede bekleme ve zaman aşımı

- AC-P13-1: Bekleme süresi saf bir fonksiyonla hesaplanır: `n`. yeniden
  deneme için `min(600 s, 30 s × 2^(n−1))`. Değerler sırasıyla 30, 60,
  120, 240, 480, 600, 600 sn'dir. Jitter yoktur (D-40). Birim testi.
- AC-P13-2: Deneme hakkı kalan, yeniden denenebilir bir hatada tarama
  `queued` olur. `retry_count` bir artar, `next_attempt_at` veritabanı
  saatine (`NOW()`) bekleme süresi eklenerek doldurulur ve `error_message`
  son hatayı içerir. Tarama `next_attempt_at` gelmeden sahiplenilmez,
  geldikten sonra sahiplenilir. Test: ilk başarısızlıktan hemen sonra
  yapılan sahiplenme denemesi taramayı almaz; `next_attempt_at` geçmişe
  çekildiğinde alır (bugünkü kodda hemen alındığı için başarısız olur).
- AC-P13-3: Toplam deneme sayısı (ilk deneme dahil)
  `system_settings.scan.max_retries` değeridir (varsayılan 3). Son deneme
  de başarısız olursa tarama `failed` olur: `completed_at` doldurulur,
  `next_attempt_at` boşaltılır ve `scan_failed` denetim kaydı yazılır.
  Test.

  ADR-004 Karar 8 ile netleştirildi (güvenlik düzeltmesi I-3):
  - **Ayar üst sınırları:** `system_settings` ve ortam değişkenlerinden
    okunan sayısal ayarlar aralık denetiminden geçer. Aralık dışı, sonlu
    olmayan veya tam sayı olması gerekirken tam sayı olmayan bir değer
    varsayılana döner ve yalnızca ayarın adını yazan bir uyarı log'lanır.
    Başlangıç durmaz. Aralıklar:

    | Ayar | Aralık |
    | --- | --- |
    | `scan.max_retries` | 1–10, tam sayı |
    | `scan.timeout_minutes` | (0, 1440] |
    | Süre sınırları (clone, rapor, ayrıştırıcı) | 1 ms – 24 sa |
    | Yoklama aralıkları | 1 ms – 1 sa |
    | Eşzamanlılık | 1–32 |

  - **Deneme hakkı tükenmiş bekleyen satır:** Sahiplenme transaction'ı,
    `retry_count >= max` olan `pending`/`queued` satırları aynı
    transaction içinde `failed` yapar (`completed_at`, `next_attempt_at =
    NULL`, açıklayıcı `error_message`) ve her biri için `scan_failed`
    kaydı yazar. Böylece `max_retries` düşürüldüğünde kuyrukta sonsuza
    kadar bekleyen satır kalmaz.
- AC-P13-4: **Kalıcı hatalar** (D-41) yeniden denenmeden hemen `failed`
  olur ve `next_attempt_at` boş kalır. Kalıcı hatalar: token çözülemedi,
  kaynak/`SCAN_ROOTS`/ref geçersiz, iş süre sınırı aşıldı, ayrıştırıcı iş
  parçacığı çöktü veya bellek sınırını aştı, ayrıştırıcı `failed` sonucu
  döndü, git yok veya sürümü 2.32'den eski. Test: en az token, geçersiz
  kaynak, süre sınırı ve iş parçacığı çökmesi için.
- AC-P13-5: **Geçici hatalar** P-13'e göre beklemeyle yeniden denenir.
  Geçici hatalar: clone hatası ve clone zaman aşımı

  tarama (AC-P12-11). Clone hataları kimlik doğrulama/bulunamadı
  ayrımı yapılmadan geçici sayılır (D-41).
- AC-P13-6: **İş süre sınırı (D-42).** Sahiplenme anında `scans.timeout_at`
  değeri `NOW() + scan.timeout_minutes` olarak yazılır (varsayılan 60 dk).

  kümelerini siler. `splitlines` ile `split('\n')` farklı ayırıcılar
  kullanır. `str()` ile `String()` farklı sonuç verir. purl farkı parmak
  izini değiştirir. Bu da bulgu kararlarının sessizce taşınmamasına
  (yeniden `open` açılmasına) ve `packages` tablosunda mükerrer kayda yol
  açar. AC-P10-4 ve AC-P10-6 bu riski azaltır. Tip olarak geçersiz manifest
  değerleri (ör. `package.json`'da metin olmayan sürüm) için birebir
  eşitlik aranmaz. Bu durumda ayrıştırıcı çökmemeli, girdi bir
  `parse_errors` kaydına ya da atlamaya dönüşmelidir.
- **Golden'ın donması.** Python silindikten sonra golden yeniden
  üretilemez. İleride beklenen çıktının değişmesi bilinçli bir karar
  (yeni D-xx) gerektirir.
- **"219" sayısı.** Rapordaki sayı orijinal repoda (`1b2b934`) ölçülmüştür.
  F1 sonrası repo (`73db78b`) `tests/fixtures` klasörleri ve değişen kilit
  dosyasıyla 496 bağımlılık üretir. D-24 güncellemesi kilit dosyasını
  yeniden değiştireceği için canlı repodaki sayı F2 sırasında da değişir.
  Bu yüzden eşdeğerlik iki dondurulmuş anlık görüntüyle ölçülür: 219
  `1b2b934` üzerinde birebir doğrulanır, 496 golden değeridir (D-26,
  AC-P10-3). Canlı repo üzerindeki sayı kabul ölçütü değildir.
- **Fixture bayt kararlılığı.** `.gitattributes` `* text=auto` kuralı
  checkout sırasında satır sonlarını değiştirebilir. Bu durumda
  `file_hash`/`size_bytes` golden'la uyuşmaz. Golden fixture klasörleri
  satır sonu dönüşümünden muaf tutulmalıdır (ör.
  `tests/fixtures/.gitattributes` ile `-text`). Bu kural fixture'lar
  eklenmeden önce konmalıdır.
- **Tek süreç.** Rapor üretimi (pdfkit/exceljs) ana iş parçacığında
  çalıştığı için büyük bir rapor API'yi birkaç saniye bekletebilir. Tek
  kullanıcı için kabul edilmiştir. Gerekirse sonraki fazda rapor üretimi
  de iş parçacığına alınır.
- **Advisory lock** (ADR-004/005 ile netleştirildi). Kilit, onu tutan
  ayrı veritabanı bağlantısına bağlıdır. Bağlantı koparsa kilit düşer ve
  bu pencerede ikinci bir örnek başlayabilir. Süreç hemen kapanmaz; bu
  davranış AC-P12-8 ile çelişirdi. Bunun yerine bozulmuş kipe geçer
  (AC-P12-15):
  - Worker'lar yeni iş almaz, API çalışmaya devam eder.
  - Kilit 5 sn'de bir yeniden denenir.
  - Kilit başka bir örnekteyse süreç düzgün kapanışla exit code 1 ile
    çıkar.

  Pencere içinde süren işlerin son yazımları `worker_id` çitiyle
  korunur, böylece iki örnek aynı taramanın sonucunu üst üste yazamaz.
  Kalan risk: pencere boyunca ikinci örneğin kendi başlangıç kurtarması,
  birinci örneğin süren taramalarını sahipsiz sayabilir. Birinci örneğin
  sonucu çit nedeniyle atılır ve tarama yeniden denenir. Veri bozulmaz,
  yalnızca iş tekrarlanır. Raporlarda sahip kolonu yoktur. Bu yüzden
  `lock-lost` kapanışında rapor süpürmesi atlanır (AC-P12-10). Rapor
  satırına sahiplik eklenmesi bir şema değişikliği gerektirir ve F3'e
  ertelenmiştir (güvenlik raporu L-5 kalıntısı, insan risk kabulü).
- **N-1 yan etkileri.** `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL` ve
  `HOME` yalıtımıyla kullanıcının global `http.proxy`, `http.sslCAInfo`,
  `insteadOf`, credential helper ve `.netrc` ayarları devre dışı kalır.
  Vekil sunucu yalnızca ortam değişkenleriyle desteklenir; PAC desteği
  yoktur. Git ortamı izin listesiyle kurulduğu için listede eksik kalan
  bir değişken git'i Windows'ta çalışmaz hâle getirebilir. Bu durumda
  liste ADR-002 Ek E1 güncellenerek genişletilir. Kurumsal vekil sunucu veya özel CA kullanan
  ortamlarda clone başarısız olabilir. Bunun karşılığı olarak Windows'ta
  schannel (Windows sertifika deposu) açıkça seçilir, vekil sunucu ortam
  değişkenleri aktarılır ve README'ye not düşülür. AC-P12-14'teki
  herkese açık `https` taraması bunu doğrular.
- **Göç aracının veri etkisi.** `down --to` veri siler. Kararın insan
  onayına tabi olduğu, yedek alma önerisiyle birlikte `db/README.md`'de
  belgelenir. Production veritabanı kapsam dışıdır.
- **Yeni bağımlılık (tedarik zinciri).** `smol-toml` taranan güvenilmeyen
  girdiyi işler. İş parçacığı içinde, bellek ve yığın sınırıyla çalışır ve
  exact pin ile sabitlenir. Security Red Team incelemesine dahil
  edilmelidir. Kütüphanenin ileride TOML 1.1 sözdizimini kabul etmesi
  Python'dan sapma doğurabilir; sürüm yükseltmesi ayrı bir karar ve yeşil
  golden testleri gerektirir.
- **D-24 override.** `uuid` 8 → 11 geçişi `exceljs`'in yalnızca kullandığı
  `uuid.v4` imzasını korur; yine de Excel çıktısı bozulabilir.
  AC-T-5'teki geri okuma testi bu riski azaltır.
- **BOM kusuru korunuyor.** BOM'lu `requirements.txt`'nin ilk satırı
  Python'da olduğu gibi atlanır (AC-P10-4). Bu bilinen bir doğruluk
  kusurudur ve sonraki fazda düzeltilmesi beklenir.
- **`db:migrate` derleme gerektirir.** `npm run build` yapılmadan
  çalıştırılan `npm run db:migrate` eski bir `dist` ile çalışabilir veya
  hiç çalışmaz. README akışı (`npm ci → npm run build → npm run
  db:migrate → npm start`) bunu sağlar.
- **Alışkanlık değişikliği.** `npm run worker` ve `bash db/migrate.sh`
  komutları ortadan kalkar. README ve `db/README.md` yeni akışı tek yerde
